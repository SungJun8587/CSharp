GameViewer - MMORPG 필드 전투 C# 뷰어
==========================================

[무엇인가]
  Gateway 클라이언트 포트에 BotClient 처럼 접속(로그인 -> 존 입장)해서 서버가 보내는 전투 패킷을 받아
  숲 필드 위에 영웅/몬스터의 이동, 공격, 스킬(시전/투사체/범위), 피해 숫자, 사망/부활, 상태 효과를
  눈으로 확인하는 도구입니다. 서버와 같은 GameData JSON(Hero/Monster/Skill/Status/HeroSkill/Block/Spawn)을
  읽으므로 이름/사거리/반경/쿨다운이 서버 값과 항상 같습니다.
  서버 없이 화면만 확인하는 데모 모드(--demo)도 있습니다.

[구성]
  Core/    플랫폼 비의존 코어(netstandard2.0, UI/엔진 참조 없음) - Unity 에서 그대로 재사용 가능
    Protocol/  패킷 상수/구조체(Parse/Build), 프레이머 (서버 ZonePacket.h 와 1:1)
    Net/       GatewayClient (수신 스레드 + 큐, 소비는 호출 스레드)
    World/     WorldModel(엔티티/연출/로그), Entity(이동 보간), ViewEffect(연출 데이터)
    Data/      MiniJson, GameData(서버와 같은 JSON 로더)
    Audio/     Sfx(효과음 합성 + 연출별 소리 규칙. 오디오 장치를 모르는 순수 데이터)
    Logic/     AutoPilot(자동 전투), DemoDirector(서버 없는 로컬 시뮬레이션)
    ViewerSession.cs  접속 흐름 + 월드 + 명령(이동/공격/스킬/쿨다운)
    ViewerConfig.cs   JSON + 명령행 옵션
  Assets/  (선택) 이미지 에셋과 sprites.json - 아래 [이미지 에셋]
  App/     WinForms 뷰어 (GDI+ 더블 버퍼). Render/ 는 System.Drawing 만 쓰는 렌더러
  Tests/   콘솔 테스트 (가짜 Gateway 왕복 포함)
  Tools/   RenderSnapshot - 서버/창 없이 데모 장면을 PNG 로 저장 (렌더러 확인용)
           <GameData> <outDir> [초...]   장면 저장 (환경변수 SNAP_BOSS=1 이면 영웅이 보스를 쫓고, SNAP_CAM=x,y 로 카메라 고정)
           --start <GameData> <outDir>    시작 화면(로딩바 3단계 + 영웅 선택) 저장
           --sheet <outDir> [배율]        스프라이트 시트    --bench <GameData> [프레임]  부분별 그리기 시간
           --selftest <GameData>          전 스프라이트/상태/해상도/배율 그리기 점검 + 이미지 에셋 로더 점검(합성 이미지)
  GameViewer.json / GameViewer.bat / GameViewer_Demo.bat

[빌드]
  GameViewer.sln 을 Visual Studio 로 열어 빌드 (".NET 데스크톱 개발" 워크로드, .NET Framework 4.8).
  .NET 8+ 로 올리려면 App.csproj 의 TargetFramework 를 net8.0-windows 로 바꾸면 됩니다.

[실행]
  1) 서버: GatewayServer 와 ZoneServer 를 띄움
  2) GameViewer.bat 실행  (GameViewer.json 의 값 사용, 명령행 옵션이 우선)
     - GameViewer.bat 안의 DATA 를 서버가 읽는 GameData 폴더로 맞춰 주세요.
     - 서버 없이 화면만 보려면 GameViewer_Demo.bat
  3) BotClient 를 같이 돌리면 뷰어 주변에서 봇들이 몬스터와 싸우는 모습을 볼 수 있습니다.
  4) 같은 PC 에서 GameViewer.bat 을 여러 번 실행하면 창이 여러 개 뜹니다. 실행마다 빈 슬롯 번호(0, 1, 2...)를 CharId 에 더해
     (900001, 900002, ...) 서로 다른 캐릭터로 입장하고, 창 제목에 캐릭터 ID 가 표시됩니다. 창을 닫으면 그 번호는 다시 쓰입니다.
     --char-id 를 직접 주거나 --single(또는 GameViewer.json 의 MultiInstance=false)이면 번호를 더하지 않고 그 ID 를 그대로 씁니다.
     서버에 같은 캐릭터 ID 로 두 번 입장할 수 없으므로(DuplicateEntity) 직접 지정할 때는 창마다 다른 값을 주세요.
  종료 코드: 0 정상, 1 옵션 오류

[조작]  (아래 키는 기본값입니다. 설정 창(F2) -> "키 설정" 에서 동작마다 바꿀 수 있습니다)
  좌클릭   땅 = 이동 / 몬스터 = 선택 + 쫓아가서 공격(스킬 포함)
  우클릭   누른 채 이동(MMO 방식), 몬스터 우클릭 = 공격
  1~9      스킬(영웅 스킬 순서). 단일 스킬은 선택한 대상(없으면 가장 가까운 몬스터), 범위 스킬은 대상 위치/커서 위치
  Q        기본 공격(대상 선택 후 접근-공격)    Tab/Shift+Tab 대상 전환    Esc 취소
  A        자동 전투(가까운 몬스터를 찾아 싸우고, 없으면 스폰 지점을 순회)
  F        시점 고정 on/off (끄면 방향키로 이동)    휠, +/- 확대/축소    Space 내 위치로
  F5 재접속(끊긴 상태에서는 자동 재접속 횟수를 처음부터 다시 셈)   F1 도움말   L 로그 표시 방식 전환(떠오르는 줄 -> 탭 로그 창 -> 끔)
  M        월드맵    F2  설정 창    Ctrl+M  효과음 켜기/끄기(기본 켜짐)    Enter  채팅 입력(탭 로그 창의 채팅 탭)
  (시작 화면) 창이 뜨면 로딩바가 GameData/이미지 읽기 진행률을 보여주고, 끝나면 영웅 선택 화면이 나옵니다. 영웅 카드에는 걷는 모습(고르거나 마우스를 올리면 움직임), 능력치 막대(영웅들 중 가장 높은 값을 100%로), 스킬 아이콘(마우스를 올리면 스킬 설명)이 있습니다. 서버에 붙는 실행은 "게임 시작" 왼쪽에 서버 목록(이름, 접속 가능 여부와 연결 시간)이 있고 클릭 또는 S 로 고릅니다. ←→/1~9/클릭으로 영웅을 고르고 Enter, [게임 시작] 버튼 또는 카드 더블클릭으로 시작합니다(그때 서버에 접속하거나 데모를 시작). --skip-select(또는 GameViewer.json 의 SkipHeroSelect=true)면 건너뛰고 --hero 영웅으로 바로 시작합니다.
  H        영웅 선택 창(↑↓/1~9/클릭으로 고르고 Enter: 그 영웅으로 다시 접속. 데모 모드는 그 영웅으로 다시 시작). 열려 있는 동안 다른 입력은 막힘
  B        보스 선택(가장 가까운 보스)    F12  스크린샷 저장(실행 파일 옆 screenshots 폴더)
  미니맵 클릭  그 위치로 이동    휠/+- 확대·축소는 부드럽게 보간

[라이브 UI]
  피격 연출   내가 큰 타격(최대 체력의 12% 이상)을 주거나 맞으면 화면이 아주 잠깐(45~70ms) 멈추는 히트 스톱과 화면 흔들림이 붙고, 내가 맞으면 맞은 쪽 가장자리가 붉게 번쩍입니다(센 타격일수록 진하고 오래감). 피해 숫자는 대상 최대 체력 대비 비율에 따라 크기가 연속으로 달라지고, 내가 준 큰 타격에는 "강타" 표시가 붙습니다. 내가 적을 연속으로 때리면(2.2초 안에 다음 타격) 오른쪽에 N HIT 와 합계 피해, 남은 시간 막대가 보입니다.
  상태 효과   내 체력바 위에 아이콘 줄(이로운 것 먼저, 해로운 것은 붉은 테두리; 남은 시간 숫자와 시계 방향 쓸어내림), 대상 창에도 아이콘으로 나옵니다. 지속 피해이거나 공격/방어/이동 속도가 깎이는 효과를 해로운 것으로 봅니다(Core/Logic/StatusLook.cs).
  보스 체력바   페이즈 경계마다 P2/P3 표시(도달한 것은 금색)와 "다음 P3 체력 25% 이하" 안내가 붙습니다.
  접속 흐름   접속 -> 로그인 -> 입장 단계와 경과 시간을 보여 주고, 연결이 끊기거나 접속에 실패하면 1/2/4/8/10초 간격으로 최대 5번 자동 재접속합니다(Core/Logic/ReconnectPolicy.cs). 재접속 중에는 마지막 화면을 유지하고, 성공하면 월드를 새로 받습니다. 로그인/입장이 서버에서 거부된 경우(이미 접속 중 등)는 자동으로 다시 시도하지 않고 F5 를 기다립니다. 데모 모드는 자동 재접속을 쓰지 않습니다.
  존 입장 연출   입장할 때 검은 화면에서 밝아지며 "ZONE n / 존 이름 / 한 줄 소개" 배너가 나오고 존 종류별 입장 효과음이 한 번 울립니다(재접속은 페이드와 짧은 효과음만). 시간표는 Core/Logic/ZoneIntro.cs.
  로그 창   L 로 바꾸는 탭 창(전체/전투/시스템/채팅, 휠로 거슬러 올라감). 전투 탭에는 내가 관련된 타격 한 번마다의 줄(누가 -> 누구 몇 피해, 남은 체력)이 쌓이고 화면 아래에 떠오르는 줄에는 나오지 않습니다. 채팅 탭의 입력은 이 뷰어 안에만 표시되며 서버로 보내지 않습니다(뷰어 프로토콜에 채팅 패킷이 없음).
  설정 창(F2)   그래픽 품질(높음: 전부 / 중간: 대기 연출 끔 / 낮음: 대기 연출과 가장자리 어둡게 하기 끔), 효과음 켜기/끄기와 크기(0~100%), 배경음악 켜기/끄기와 크기(0~100%, 효과음과 따로), FPS/네트워크 정보 표시, 피해 숫자 표시, 화면 효과(저체력/피격) 켜기/끄기, 화면 흔들림 줄이기, 타격감 세기(0~150%, 100% 가 기본: 히트 스톱 길이/피격 번쩍임/화면 흔들림에 곱함), 키 설정. 바꾸면 바로 실행 파일 옆 settings.json 에 저장되고 다음 실행에 복원됩니다. 효과음/배경음악 크기는 소리 샘플 자체를 줄여서 적용합니다.
  키 설정   동작 14개(기본 공격, 보스 선택, 자동 전투, 카메라 고정/가운데, 대상 전환, 도움말, 로그 창, 채팅, 설정, 월드맵, 영웅 선택, 스크린샷, 재접속)와 스킬 1~9 의 키를 바꿉니다(Enter 또는 클릭 후 새 키, Delete 는 그 항목 기본값, R 은 전부 기본값). 한 키는 한 동작에만 묶여서 이미 쓰는 키를 고르면 두 동작이 키를 맞바꿉니다. Esc, 방향키, Shift/Ctrl/Alt, 숫자패드 1~9(스킬 1~9 와 같이 동작)는 쓸 수 없고 Ctrl+M(효과음 끄기)은 고정입니다. 도움말, 스킬 칸의 키 표시, 시작 화면의 안내는 바꾼 키를 따라갑니다. 규칙은 Core/Logic/KeyBindings.cs (키 값은 Windows 가상 키 코드).
  스킬 툴팁   스킬 칸(기본 공격 포함)에 마우스를 올리면 이름과 키, 모양/대상, 사거리/반경/각도/최대 대상, 재사용/시전 시간, 피해/치유 비율, 부가 효과(이름, 지속 시간, 지속 피해/능력치 증감), 남은 재사용 시간이 나옵니다. 값은 서버가 쓰는 Skill/Status/Hero 표에서 만듭니다(Core/Logic/SkillTip.cs).
  배경음악   존 종류(숲/사막/설원/화산/늪/폐허/해안/수정굴/천상/암흑)마다 다른 곡이 16초 길이로 반복됩니다(드론 + 코드 패드 + 드문 멜로디 + 존 질감). 시야에 보스가 있으면 같은 조(調)의 전투 곡(박자와 베이스/아르페지오가 붙음)으로 바뀌고, 보스가 사라진 뒤 6초가 지나야 평온한 곡으로 돌아갑니다(Core/Logic/BgmDirector.cs). 곡은 외부 음원 없이 코드로 합성하며(Core/Audio/Bgm.cs) 끝과 처음이 이어져 끊김이 없습니다. 재생은 Windows 멀티미디어(MCI)로 하며 곡을 임시 폴더(GameViewer_bgm)에 WAV 로 쓰고 종료할 때 지웁니다. 창이 비활성이 되면 멈추고 돌아오면 이어서 틉니다. Windows 가 아니거나 재생이 실패하면 소리 없이 넘어갑니다.
  서버 선택   GameViewer.json 의 Servers 목록([{"Name","Host","Port"}])이 시작 화면의 서버 칸이 됩니다. 비어 있으면 Host:Port 하나가 "기본 서버" 로 나오고, 명령행으로 준 --host/--port 가 목록에 없으면 "직접 지정" 이 덧붙습니다. 처음 고르는 서버는 명령행 주소 > 마지막에 고른 서버(settings.json 의 LastServer) > Host:Port 순입니다. 각 서버에는 TCP 접속만 해 보고(패킷은 보내지 않음) 10초마다 연결 시간을 갱신하며, 게임 중 핑(패킷 왕복)은 아닙니다(Core/Net/ServerProbe.cs). 데모 모드에는 서버 칸이 없습니다.
  월드맵(M)   존 전체 지도: 서식지(몬스터 이름/마릿수, 보스는 ★), 장애물, 물/용암, 플레이어/몬스터/보스, 내 위치와 방향, 현재 화면 범위, 좌표 격자. 휠로 커서 기준 확대(최대 8배), 드래그로 이동, 클릭하면 그 지점으로 이동하며 닫힙니다. 좌표 변환은 Core/Logic/MapProjection.cs.

[화면]
  숲 바닥(연두 초원/그늘/햇빛 얼룩, 구불구불한 흙길, 풀 무더기/꽃밭/이끼 바위)과 나무/바위(Block.json 의 Circle=나무, Rect=바위), 반딧불과 햇살, 연못(Block 의 Rect 중 ZoneTheme 의 연못 좌표와 같은 것을 물로 그린다. tools/make_forest_water.py), 단풍/새순/활엽수로 나무 변주, 영웅(전사/궁수/마법사 색과 무기), 몬스터(종류별 색),

[이미지 에셋]  (선택. 사진/3D 렌더 같은 그림을 쓰려면)
  실행 파일 옆 Assets\sprites.json 에 적은 종류만 이미지로 그리고, 나머지는 위의 코드로 그린 그림을 그대로 씁니다. 파일이 없으면 모두 코드 그림입니다.
    { "sprites": [ { "kind": "monster", "template": 5, "pattern": "demon/{0:000}.png", "angles": 18, "height": 4.6 } ] }
    kind monster|hero|tree, template = Monster/Hero 시트의 Id (tree 는 없음: Block 의 원 = 나무 전부를 이 이미지로 그림, height 는 반경 1 일 때 높이), pattern = sprites.json 기준 경로({0} = 각도(도)), angles = 방향 수(1..72),
    height = 그림 내용이 차지할 높이(단위, 0.5..12). 각도 = 번호*360/angles. 0도는 화면 아래(카메라 쪽)를 보는 모습이고
    커질수록 화면 오른쪽 -> 위 -> 왼쪽으로 돕니다. 이미지는 PNG/JPG/GIF/BMP(투명 배경은 PNG)이며 WebP 는 GDI+ 가 못 읽습니다.
  - 모든 방향의 불투명 영역을 합친 상자로 발 밑과 크기를 잡으므로 돌 때 흔들리지 않고, 클릭 판정/체력바 높이도 이 크기를 따릅니다.
  - 걷기 애니메이션(선택): 항목에 "walkFrames": 6, "walkPattern": "wolf/walk_{0:000}_{1:00}.png" 를 더하면({0}=각도, {1}=프레임 번호 0부터, 2..32장) 걸을 때 걸은 거리에 맞춰 프레임을 넘깁니다.
    서 있을 땐 pattern 그림을 씁니다. 걷기 프레임이 없는 종류는 걸을 땐 튀고 설 땐 숨 쉬듯 눌러서 흉내 내며, 피격 번쩍임/시체는 둘 다 같은 방식으로 처리합니다.
    걷기 이미지는 기본 이미지와 같은 크기여야 하고, 크기/발 밑 기준은 걷기 프레임까지 합친 범위로 잡습니다.
  - 영웅 상태 그림(선택): "idleFrames": 8, "idlePattern": "warrior/idle_{0:000}_{1:00}.png", "hitPattern": "warrior/hit_{0:000}.png", "deathFrames": 3, "deathPattern": "warrior/death_{0:000}_{1}.png".
    대기 그림은 무기를 뺀 몸이 숨 쉬듯 오르내리고 머리카락/망토가 흔들리며 한 프레임은 눈을 감습니다(260ms 마다 한 장씩, 영웅마다 시작이 다름). 손 위치는 anchors.json 의 "idleGrip"([방향][프레임])으로 무기 그림을 따라 옮깁니다.
    피격(맞은 뒤 260ms)과 사망(쓰러지는 중 -> 거의 누움 -> 누워 있음, 420ms)은 무기까지 구운 그림 한 장이라 무기 레이어를 따로 얹지 않고, 마지막 사망 그림이 시체로 남습니다. 이 그림들은 처음 쓸 때 읽어서 메모리를 아낍니다. 없으면 대기는 눌러서 숨 쉬는 흉내, 사망은 납작한 시체를 씁니다.
  - 잘못된 항목(파일 없음, 크기 불일치, 값 범위 등)은 그 항목만 건너뛰고 표준 오류에 "assets: ..." 로 적습니다.

[오리지널 영웅]
  Assets\warrior, archer, mage, lancer  스타일라이즈드 3D 느낌(셀 셰이딩 + 외곽선)으로 직접 렌더한 영웅. 각 18방향(정지) + 방향마다 걷기 8프레임. 외부 모델/텍스처를 쓰지 않았습니다.
  걷기: 8프레임 한 주기에 두 발이 벌어진 순간(접지)과 다리가 몸 아래를 지나는 순간이 모두 들어 있고, 딛은 발이 늘 바닥에 닿도록 엉덩이 높이가 정해져 접지 때 가장 낮고 통과 때 가장 높다. 몸통 위쪽은 딛은 발 쪽으로 조금 쏠린다. 딛은 발은 땅에서 일정한 속도로 뒤로 밀리고(발 위치를 먼저 정하고 다리 각도를 역산), 든 발은 발꿈치부터 떼어 올린다. 프레임 한 장은 스프라이트 20픽셀(HeroStridePx × asset.Scale)만큼 걸을 때마다 넘어가 발이 땅에서 미끄러지지 않는다.
  접지: 엔티티 밑에 겹친 타원 3장 그림자(발 밑이 중심, 뜰수록 작고 옅음)가 몸이 밀린 자리를 따라가고, 몬스터 근접 공격은 덮치는 포물선/착지 눌림과 착지 먼지(내려찍기는 충격 고리 포함)를 낸다. 걷기 프레임 없는 몬스터의 걸음 통통거림은 0.07 단위로 줄여 땅에서 뜨지 않게 했다.
  무기 분리(전사 검, 궁수 활, 마법사 지팡이, 창기사 창): 몸 그림에는 무기가 없고 무기는 따로 그린다. 네 영웅 모두 공격 자세 5장(attackFrames 5, poses 6)을 3D로 팔과 무기를 함께 렌더한다(전사 위로 들기→내려베기→찌름, 궁수 시위 당김→놓음, 마법사 지팡이 올림→내지름). HeroWeapons 는 무기를 그리지 않고 검 궤적/화살 비행/구슬 빛/불꽃 같은 효과만 앵커를 따라 얹는다(SpriteFx). 무기 그림이 없는 에셋은 예전 코드 그리기로 대체된다.
  창 분리(sprites.json): "attackFrames": N, "attackPattern": "lancer/atk_{0:000}_{1}.png"({0}=각도, {1}=공격 자세 0..N-1) 와
    "weapon": { "poses": N+1, "pad": 160, "backPattern": ..._{0}_{1:000}_b.png, "frontPattern": ..._f.png, "anchors": "lancer/anchors.json" } ({0}=자세, {1}=각도).
    자세 0 은 대기/걷기, 1.. 은 공격 자세. 창 그림은 몸 그림 둘레에 pad 픽셀 여백을 둔 같은 카메라 그림이라 몸 그림 (-pad,-pad) 에 맞춰 찍으면 겹친다.
    뷰어는 창 뒤쪽 -> 몸 -> 창 앞쪽 순으로 찍고, 걸을 때는 walkGrip 으로 창을 프레임별 손 위치에 옮기며, 찌르기 잔광/불꽃/기모으기 빛은 창끝 앵커를 따라간다.

  표정: 얼굴은 normal/blink(눈 감음)/hurt(눈 ><, 입 벌림)/shout(기합: 눈 치켜뜸, 입 크게)/dead(눈 X) 가 있고, 공격 몸 그림은 기합, 피격은 hurt, 사망은 hurt -> dead 로 그립니다.

  시작 시 걷기 그림은 크기 계산에만 잠깐 읽고 버린다. 데모 9000프레임(약 2.4분) 기준 프로세스 메모리 약 2.3GB(구동 직후부터 1.5GB) -> 약 0.42GB(Mono 소프트웨어 렌더 측정, `Snap.exe --memprobe`).
- 시작 화면 서버 목록은 화면 높이에 맞춰 줄 수가 정해진다(StartScreen.ServerRows).

[몬스터 피격/사망 자세]
- 몬스터 그림은 방향별 2D 한 장이라 3D 로 다시 그릴 수 없어, 공격 자세와 같은 방식으로 그림을 휘어 굽는다(tools/bake_monster_poses.py, gv 폴더에서 실행).
  hit_<각도>.png 는 맞은 쪽으로 젖히고 눌린 한 장, death_<각도>_<0..2>.png 는 휘청 -> 쓰러지는 중 -> 누움(발 밑을 축으로 옆으로 넘어져 납작해짐). 마지막 그림이 시체로 남는다.
  옆으로 넓은 몸(게)은 옆으로 눕지 않고 배를 드러내며 뒤집힌다.
- sprites.json 의 몬스터(보스판 포함)에 hitPattern / deathFrames / deathPattern 이 적힌다. 영웅과 같은 로더를 쓰고 처음 쓸 때 읽는다. 그림이 없으면 예전의 납작한 시체로 대신한다.
- 확인: Snap.exe --monpose <GameData> <out.png> (서 있기/피격/사망 3단계 시트).
- 표정은 없다: 몬스터 얼굴이 그림에 구워져 있어 눈/입 위치를 알 수 없고, 코드로 덧그리면 그림과 어긋난다.

[몬스터 3D 렌더]
- 슬라임/버섯/선인장/폭탄/불꽃/큰 뱀/게 7종은 도형으로 만든 3D 모델을 렌더한다(tools/render_monsters.py, gv 폴더에서 `python3 tools/render_monsters.py --export Assets Assets/sprites.json`, 그림만 다시 쓰지 않고 json 만 갱신하려면 --json-only).
  방향 4개 x (서기, 걷기 6, 공격 5, 피격 1, 사망 3, 대기 8). 걷기는 걸음마다 뛰기(슬라임)/뒤뚱(버섯·선인장·폭탄·게)/구불(큰 뱀)/일렁임(불꽃)으로 다르다. bounds 가 있으면 걷기 그림은 크기 계산에 들어가지 않는다. 표정(보통/깜빡/아픔/화남/X눈)이 자세마다 바뀐다. 렌더는 400, 게임용은 200x200 으로 줄여 쓴다(EXPORT_SIZE).
  모델은 +z 가 앞이고 몬스터마다 ZOOM 이 있어 쓰러지거나 뛰어올라도 그림 밖으로 나가지 않는다. 늑대 모델(build_wolf)은 시험판이라 쓰지 않는다.
- sprites.json 의 해당 항목에는 "render":"3d", "bounds"(모든 자세를 합친 상자), "footPx"(땅에 닿는 줄)가 적힌다. 뷰어는 height 와 Look(이름표/그림자/효과 위치)을 서 있는 그림 기준으로 두고, 그림을 담는 비트맵 크기(AssetSet.Extent)만 bounds 기준으로 잡는다.
- 그림을 휘어 굽는 bake_monster_attacks.py / bake_monster_poses.py 는 "render":"3d" 인 몬스터를 건너뛴다. 나머지 몬스터(늑대, 고블린 계열, 나무 정령, 기사 등)는 그 방식을 쓴다.

[몬스터 사망 연출]
- 죽는 순간 한 번 튀어 오르고(320ms), 시체는 1.5초 뒤부터 서서히 투명해져 2.5초에 사라진다(WorldRenderer, CreatureRenderer.Alpha). 모든 몬스터에 적용된다.

[피격 반응 세기]
- 맞을 때의 반동 거리/기울기/지속시간(240~370ms)과 번쩍이는 시간(90~150ms)은 최대 체력 대비 피해량(Entity.HitPower, 15% 이상이면 최대)에 비례한다. 죽을 때는 마지막 타격의 방향으로 그 세기만큼 미끄러진다(보스 제외). 규칙은 Core/Logic/AttackPose.cs(HitReactMs/FlashMs/DeathSlide).

[보스 연출]
- 등장: 보스가 처음 보이면 1.4초 동안 하늘에서 빛기둥과 함께 내려와 착지하고 바닥에 충격 고리가 번진다(몸은 중간쯤부터 나타난다). 경고 배너/흔들림은 그대로다.
- 페이즈 변신: 페이즈가 오르면 1.1초 동안 웅크렸다 부풀어 오르며(페이즈가 높을수록 조금 더 크게) 붉은 섬광과 퍼지는 고리(최대 3겹)가 나온다. 페이즈 2 이상은 발 밑에 옅은 붉은 빛이 늘 깔린다(PhaseAura, 최대 0.35).
- 사망: 섬광, 하늘로 솟는 빛기둥, 퍼지는 충격 고리 3겹, 파편 18개(1.8초). 빛기둥은 위로 갈수록 옅어진다. 흔들림 900ms/히트스톱 160ms.
- 그림은 새로 만들지 않고 코드로만 그린다. 규칙은 Core/Logic/BossFx.cs, 그리기는 WorldRenderer(등장/변신)와 Effects.DrawBossDeath(사망).

[피해 숫자]
- 최대 체력 대비 비율로 등급을 나눈다(4% 큼 / 12% 강타 / 25% 치명). 등급이 오를수록 글자가 커지고, 강타 이상은 떠오르는 첫 0.3초 동안 좌우로 떨리며 "강타"/"치명" 표시가 붙는다(내가 준 피해만). 회복 숫자는 회복량 비율에 따라 커진다.
- 패킷에 치명타/약점 표시가 없어서 실제 치명타 여부가 아니라 피해 비율로 구분한다. 규칙은 Core/Logic/DamageStyle.cs.

[날씨와 낮밤]
- 지역 종류와 시각만으로 정해진다(서버 정보 아님, 같은 지역/시각이면 항상 같은 결과). 날씨는 2분 30초 구간마다 맑음/안개/비/폭풍 중 뽑고 경계에서 25초에 걸쳐 섞인다. 낮밤은 12분에 한 바퀴이고 시작은 낮이다.
- 숲/늪/해안은 비와 폭풍(번개 섬광), 설원/사막은 안개(먼지)만, 하늘은 안개/비, 화산/수정동굴/어둠 지역은 날씨와 낮밤이 없다(밤 어두움 정도는 지역마다 다르다).
- 설정 창 "날씨 / 낮밤"으로 끈다. 번개 섬광은 "화면 효과" 설정이 꺼져 있으면 나오지 않는다. 미니맵 아래에 "밤 · 비" 같은 문구가 붙는다. 규칙은 Core/Logic/WeatherRules.cs, 그리기는 App/Render/WeatherLayer.cs.

[맵 장식]
- 바위/덤불/그루터기/꽃/버섯/수정/기둥 조각/갈대 16종을 3D 로 렌더해(tools/render_props.py, `cd tools && python3 render_props.py ../Assets/props`) 종류마다 3가지 모양으로 둔다(Assets/props/<이름>_<번호>.png, 약 0.5MB).
- 지역 종류별 후보 표(DecorRules.Table)에서 9칸 격자마다 결정적으로 뽑고 나무/바위/물 위는 피한다. 높음 품질 30%, 보통 16%, 낮음은 놓지 않는다. 엔티티와 같이 Y 순서로 그려서 앞뒤가 맞는다. 그림이 없으면 아무것도 그리지 않는다.

[지도]
- 월드맵(M)에는 확대/드래그/클릭 이동/서식지/보스/범례가 원래 있었다. 여기에 이동 목적지 표시(점선과 맥박 치는 X)를 더했다. 미니맵에는 지역 이름, 날씨 문구, 보스 맥박 고리, 이동 목적지를 더했다.
- 파티원 표시는 서버가 파티 정보를 보내지 않아 없다.

[장시간 구동 점검]
- `mono Snap.exe --soak <GameData> <분>` : 데모를 실제 시계로 N분 동안 가능한 빨리 그리며 2분 30초마다 지역을 바꾸고(캐시 교체 확인) 1분마다 프레임 시간, 33ms 초과 수, 관리 메모리, 프로세스 메모리를 찍는다. Mono 소프트웨어 렌더라서 실제 Windows 의 GDI+ 프레임 시간과는 다르다.

[스킬 이펙트 3D 스프라이트]
- 화염구 핵(fireball_0..7, 55ms마다 바뀌어 일렁임)과 화살(arrow)을 3D 로 렌더했다(tools/render_fx.py, `cd tools && python3 render_fx.py ../Assets/fx`). 화염구 스타일의 불꽃 꼬리와 화살 궤적 글로우 위에 얹어 그린다. 그림이 없으면 코드로 그린 모양을 쓴다(App/Render/FxSprites.cs).
- 베기/번개 등 다른 스킬 이펙트는 코드로 그린 그대로다.

[밤 광원]
- 밤(또는 해가 없는 수정동굴/어둠 지역)에는 밤 색조를 깐 뒤에 광원을 덧그린다(WorldRenderer.DrawLights): 수정/용암 바위와 버섯은 스스로 빛나고, 내 영웅 둘레는 따뜻하게 밝아진다. 광원 세기는 WeatherRules.LightNeed.

[맵 장식 군집]
- 배치 밀도는 넓은 값 노이즈(DecorRules.Field)를 따라 빽빽한 군집/보통/공터로 나뉘고, 군집 안에서는 같은 종류가 모인다(덤불 숲, 바위 지대 등). 바닥의 길/얼룩은 원래 지형 렌더에 있다.

[스킬 이펙트 3D 스프라이트]
- 화염구(8프레임)·화살·초승달 베기·창끝·단검·파편·독 방울·치유/노바 구슬·포효 충격 뿔은(스킬 팔레트색으로 55% 물들여 그린다) tools/render_fx.py가 만든 Assets/fx 스프라이트로 그린다(FxSprites). 파일이 없으면 기존 2D 도형으로 대체된다.

[지형 디테일]
- 흙길에는 바퀴 자국과 가운데 풀 띠가 깔리고, 길 가장자리에는 풀 덤불·자갈·고사리가 놓인다(GroundRenderer).
- 웅덩이/호수/용암 둘레에는 종류별 색의 젖은 둑 띠가 먼저 깔린다(BiomePools.WetBank). 존 가장자리의 어두운 띠는 노이즈로 흔들려 직선이 되지 않는다. 존 간 블렌딩은 없다(이웃 존 정보가 없다).

[검증 도구 메모]
- --views 에 VIEWMAP=1 을 주면 월드맵 창과 이동 목적지 마커(점선+X)를 함께 그린다.
- --soak 는 80ms 넘는 프레임을 그 프레임의 GC 횟수와 함께 한 줄씩 출력한다.

[핑(왕복 지연)]
- 존 안에서 2초마다 ZcPingReq(seq, 클라이언트 시각)를 보내고, 서버가 즉시 돌려주는 ZcPongNotify(seq/시각 에코)로 RTT 를 클라이언트 시계만으로 계산한다(PingMeter). 5초 안에 응답이 없으면 손실로 센다.
- 설정의 FPS 표시가 켜져 있으면 정보 창에 최근 핑·최근 8회 평균/최대·상태(좋음 80ms 미만 / 보통 150ms 미만 / 나쁨)·손실 수를 보여 준다.
- 데모 모드는 30~70ms 의 가짜 지연으로 응답한다.

[공기 연출 빛줄기]
- 숲의 빛줄기는 아주 천천히 움직이므로 반해상도 층에 4Hz 로만 다시 그리고, 프레임마다는 그 층을 한 번 깐다.

[공용 수학 도우미]
- S자 보간·이징·클램프·0xRRGGBB 섞기는 Core 의 Mx 한 곳에 있고, 바닥/스킬/공격 렌더러는 이를 부른다.
- --soak 는 구간별(바닥/나무/월드/대기/날씨+광원/비네트/긴장/HUD) 프레임당 시간을 함께 출력한다.

[외곽선 글자 캐시]
- 외곽선 글자(이름표, 체력 숫자, 피해 숫자, HUD 글씨)는 DrawString 을 5번 부르는 비싼 그림이라, (글자, 글꼴, 색, 정렬, 배율 1/8 단위)마다 한 번만 비트맵으로 그려 두고 그 비트맵을 찍는다(Resources.OutlinedText). 투명도는 찍을 때 곱한다.
- 변환이 회전이거나 비균일 배율이면 직접 그린다. 상한 600장이고, 가득 차면 한동안 안 쓴 것부터 비운다. 환경변수 GV_NOTEXTCACHE=1 로 끄고 비교할 수 있다(--selftest 가 두 방식의 자리/크기가 같은지 점검한다).

[틱 예외 보호]
- 타이머 틱(패킷 처리, 자동 전투, 카메라, 소리) 전체를 감싸서 예외가 나도 창이 죽지 않는다. 오류는 첫 번째와 이후 600틱마다 한 번만 로그에 남긴다. 패킷 처리 중 예외는 그 패킷만 버린다.

[성능 측정]
- --soak 는 구간별(바닥/나무/월드/대기/날씨+광원/비네트/긴장/HUD), 월드 안 구간별(바닥 이펙트/정렬/나무/장식/엔티티/공중 이펙트/머리 위 표시), 공중 이펙트 종류별 프레임당 시간을 찍는다.

[몬스터 3D 전환 마무리]
- 늑대, 고블린(일반/주술사/전사), 나무정령, 암흑기사, 강철기사도 tools/render_monsters.py 의 3D 모델로 그린다(걷기 6 / 대기 8 / 공격 5 / 피격 / 사망 3, 방향 4). 몬스터 14종 전부 render:'3d' 이다.
- 갱신: python3 tools/render_monsters.py --export Assets Assets/sprites.json (--json-only 는 그림은 두고 sprites.json 만).

[시작 첫 프레임 예열]
- 영웅 선택 화면에 처음 들어올 때 GameCanvas.PrewarmScene 이 버려 둘 데모 장면을 화면 밖에 3프레임 그려 JIT 와 첫 스프라이트 읽기, 글자/펜/붓 캐시를 데운다.

[타격 스파크]
- AttackEffects.Hit 의 중력 불꽃 점은 번짐 비트맵을 늘려 찍지 않고 타원 두 개로 그린다. 펜/붓 알파는 16 단계로 묶어 캐시가 불어나지 않게 한다.

[신규 몬스터 6종 (템플릿 15~20)]
- 박쥐(15, 비행), 독거미(16), 해골 전사(17), 바위 골렘(18), 유령(19, 비행·반투명), 독전갈(20). tools/render_monsters.py 의 사실적 셰이딩(shade_real, REAL/MATERIAL)으로 그린 3D 스프라이트이며 Assets/<이름>/ 과 sprites.json 에 등록돼 있다.
- GameData: Monster 15~20, Skill 33(뼈 투척) 34(거미줄) 35(분노의 일격) 36(독침), 존 1~10 Spawn 에 서식지가 추가됐다(GameData.xlsx, GameData_split/*.xlsx, GameData/*.json 모두).
- 사실적 셰이딩 대상: 위 6종 + 늑대, 고블린 3종, 나무정령, 암흑/강철 기사. 나머지 7종은 만화풍 3D.

[Windows 타이머]
- MainForm 타이머를 8ms 로 걸고 14ms 보다 일찍 들어온 틱은 건너뛴다. Windows 폼 타이머는 약 15.6ms 단위로만 깨어나 Interval 16 이면 31ms(약 32fps)가 되기 때문이다.
- 사실적 셰이딩 대상에 버섯, 선인장, 큰 뱀이 추가됐다(슬라임/폭탄/불꽃/게는 광택과 눈 표현이 만화풍이 나아 그대로 둔다).

[신규 몬스터 보스판 (템플릿 115~120)]
- 박쥐/독거미/해골/골렘/유령/전갈 각각 보스 템플릿이 있다(Monster 115~120, Boss/BossPhase/BossAction 15~20). 그림은 일반판과 같은 스프라이트를 쓰고 sprites.json 에서 키를 1.8배, 공격을 slam 으로 둔다. 능력치는 기준값이라 밸런스 조정이 필요하다.

[존 사이 관문 (ZoneLink)]
- GameData 의 ZoneLink 표(ZoneId, Edge W/E/N/S, Pos, Width, TargetZone, TargetX, TargetY)가 존 가장자리 관문을 정한다. 표가 없으면 관문 없이 그대로 동작한다.
- Core/Logic/ZoneGates.cs 가 관문 근접도와 건너편 지형을 계산한다. GroundRenderer 는 관문 가까이에서 바닥 색을 건너편 지형으로 섞고, GateRenderer 가 기둥/화살표/존 이름을 그린다.
- 존을 실제로 넘어가는 처리(서버 이전)는 서버에 아직 없어, 클라이언트는 표시만 한다.

[보스 연출]
- 등장: 빛기둥에서 내려와 착지하면 화면이 흔들리고(설정의 흔들림 배율 적용) 발 밑에 바닥 균열이 퍼진다. 착지와 페이즈 변신 순간에는 화면이 짧게 번쩍인다(화면 효과 설정을 끄면 번쩍임이 없다).
- 보스 발 밑에는 느리게 도는 마법진(이중 고리 + 오각 별 + 다섯 점)이 늘 깔리고, 페이즈가 오를수록 선명해진다.
- 보스 고유색: 박쥐 보라, 독거미 초록, 해골 청백, 골렘 주황, 유령 청록, 전갈 호박색(BossFx.Theme). 빛기둥, 마법진, 균열, 변신 섬광이 이 색을 쓴다. 그 밖의 보스는 금색/붉은색이다.
- 확인: SNAP_BOSSTPL=<몬스터 템플릿> Snap.exe --bossfx <GameData> out.png 는 그 템플릿으로 등장/착지/균열/변신을 한 장에 그린다.

[존 관문 통과 (데모 모드)]
- 영웅이 관문 안쪽 가장자리(3 이내)에 닿으면 화면이 어두워지고(0.45초), 건너편 존의 GameData 를 읽어 ZoneLink 의 도착 지점에서 새로 시작한다(입장 연출과 배너가 이어진다). 도착 직후 3초는 다시 관문이 반응하지 않는다. 자동 전투 상태는 유지된다.
- G 키: 가장 가까운 관문으로 걸어간다(F1 도움말에도 있다). 순서(닿음 -> 어두워짐 -> 교체 -> 쉬는 시간)는 Core/Logic/GateTravel.cs 가 정한다.
- 확인: Snap.exe --gatetravel <GameData> <prefix> 가 관문 앞 / 어두워지는 중 / 도착 장면을 prefix0~2.png 로 저장한다.
- 서버 모드는 존 이동을 서버가 정하므로 이 동작을 하지 않는다.

[보스 전용 공격 연출]
- 새 보스 6종은 타격 연출(sprites.json 의 fx)이 각각 다르다(MonsterFx): 박쥐 bossbat(초음파 고리 다섯 겹), 독거미 bossvenom(독 웅덩이/거미줄/독방울), 해골 bossbone(발 밑에서 솟는 뼈창), 골렘 bossquake(충격파/바위 조각/먼지), 유령 bosswail(청록 울음 고리/영혼 불꽃), 전갈 bossstinger(내리꽂는 꼬리 침/독방울).
- 확인: SNAP_TPLS=115,116 Snap.exe --monfx out.png 30 1 0.3 은 그 템플릿들의 공격 장면(0~440ms)을 한 장에 그린다.

[존 테마 몬스터 6종 (템플릿 21~26, 보스판 121~126)]
- 설인(설원, 존 3/10), 용암 도마뱀(화산, 존 4/2/6), 늪 두꺼비(늪, 존 5/7), 바다 소라게(해안, 존 7), 수정 사마귀(수정 동굴, 존 8/9), 폭풍 독수리(하늘, 존 9). 모두 3D 렌더 스프라이트(tools/render_monsters.py)이고 sprites.json 에 타격 연출(fx)이 연결돼 있다.
- 보스판은 같은 그림을 1.8배로 쓰며, 각자 전용 타격 연출이 있다: bossfrost(얼음 기둥/서리 충격파), bosslava(용암 고리/불덩이), bossvenom(독 웅덩이), bosstide(물결 고리/조개 파편), bosscrystal(수정 낫 궤적/수정 조각), bossgale(바람 줄기/번개). 고유색도 BossFx.Theme 에 있다.
- 몬스터 능력치와 스킬(38~42: 서리 충격, 용암 분출, 수정 베기, 독 혀, 집게 내려치기)은 GameData 의 Monster/Skill/Spawn/Boss/BossPhase/BossAction 에 있다. 보스 능력치는 기준값이다.

[그림자]
- 캐릭터 발 밑에는 접지 그림자(겹친 세 타원)가 깔리고, 키가 큰 몸은 빛 반대쪽(오른쪽 아래)으로 긴 그림자를 드리운다. 스프라이트의 림 라이트(왼쪽 위)와 같은 방향이며, 길이는 키에 비례하고 뜰수록 짧고 옅어진다.
- 그림자 색과 짙기는 존 분위기를 따른다: 설원/하늘은 푸르고 옅게, 사막/해안은 따뜻한 갈색, 화산/어둠/수정/늪은 짙고 어둡게(WorldRenderer.ShadowTone).

[3D 이펙트 스프라이트]
- 덩어리가 있는 이펙트는 3D로 렌더한 그림(Assets/fx, tools/render_fx.py)을 쓰고, 그 위에 글로우/파티클을 코드로 얹는다. 화염구, 화살, 초승달, 창끝, 단검, 파편, 독 방울, 빛 구슬, 포효 뿔이 해당한다.
- 몬스터 보스 공격도 같은 방식이다: 해골 보스의 뼈창(bonespike), 설인/유령 계열의 얼음 가시(icespike_0..1), 수정 사마귀의 수정(crystal_0 청록/1 분홍), 골렘의 바위 조각(rock_0..2). 위로 솟는 그림은 밑 중심을 바닥에 두고 높이로 크기를 정한다(FxSprites.DrawUp).
- 그림 파일이 없으면 코드로 그린 다각형 모양으로 대신한다.

[전사 영웅 장비]
- 전사는 은빛 큰 견갑(금테), 붉은 흉갑 판(윗단 금테, 가운데 금선), 허리띠 버클, 앞 허리갑옷 쪽판, 망토 아랫단 금테를 갖춘다. 모두 몸 쪽 장비라 손/무기 앵커(anchors.json)와 공격 그림은 그대로 맞는다.
- 재생성: python3 tools/render_heroes.py warrior <폴더> --walk 8, 이어서 --extra. 결과 그림에는 마감 보정(림 라이트 등)을 한 번만 적용한다.
- 궁수: 화살통(깃 달린 화살), 가죽 허리띠와 버클, 가죽 팔목 보호대. 마법사: 로브 밑단 금테, 허리 장식띠와 보주. 창병: 큰 금빛 견갑. 전사와 같이 몸 쪽 장비만 더해 앵커가 그대로이며, 재생성 명령도 같다(직업 이름만 바꾼다).
- 전사 재질: 금속(광택 0.7 이상)은 하늘/땅 반사 띠와 지평선 하이라이트로 칠한다(환경변수 HERO_METAL=1 로 재렌더). 팔레트는 진홍 옷, 짙은 금, 차가운 강철색. 
- 전사 체형: 머리와 머리카락을 목 아래 기준 84%로 줄이고, 몸통과 장비의 좌우 폭을 88%, 앞뒤 폭을 93%로 줄여 어깨가 넓은 날렵한 실루엣을 만든다(환경변수 HERO_SLIM=1 로 재렌더). 팔/다리/무기는 그대로라 앵커는 변하지 않는다. 
- 네 직업 모두 금속 재질과 날렵한 체형을 쓴다. 머리/몸통 좌우/몸통 앞뒤 비율은 SLIM_P 에 직업별로 있다(전사 .84/.88/.93, 궁수 .86/.90/.94, 마법사 .86/.92/.95, 창병 .84/.88/.93). 재생성: HERO_METAL=1 HERO_SLIM=1 python3 tools/render_heroes.py <직업> <폴더> --walk 8, 이어서 --extra.
- 얼굴/실루엣(HERO_LOOK=1): 윗눈꺼풀 선과 직업별 눈썹 기울기(BROW), 전사의 금빛 머리띠 날개, 궁수의 긴 망토, 마법사의 큰 소매와 소매 금테, 창병의 투구 깃털. 마법사 로브 밑단 금테는 눕혀도 판처럼 보이지 않게 구슬 고리로 만들었다.
- 네 직업을 다시 만드는 전체 명령: HERO_METAL=1 HERO_SLIM=1 HERO_LOOK=1 python3 tools/render_heroes.py <직업> <폴더> --walk 8, 이어서 --extra (직업당 10분 안팎, 2코어 기준).

[기본 몬스터 디테일]
- 슬라임(몸 속 방울, 흘러내린 방울, 볼터치, 젖은 광택), 버섯(기둥 목 주름, 갓 두께, 점, 발밑 풀잎), 선인장(세로 골, 뾰족한 가시, 꽃잎), 폭탄(쇠 띠와 리벳, 불똥), 불꽃(불씨, 바닥 그을음), 지렁이(등 가시, 이빨), 게(등딱지 혹과 가시, 따개비)는 부품을 더해 만든다. 보스판도 같은 그림을 쓴다.
- 일곱 종만 다시 만들려면 tools/render_monsters.py 의 _export_one 을 그 이름들로 돌린 뒤 마감 보정을 한 번 적용하고, --export <Assets> <sprites.json> --json-only 로 bounds 를 갱신한다.

[재질별 피격/사망 연출]
- 몬스터는 재질(HitMaterial: 살점, 젤, 식물, 나무, 뼈, 돌, 금속, 껍질, 불, 영기)에 따라 맞을 때 조각이 튀고(MaterialFx.Debris) 죽을 때 터진다(MaterialFx.Burst). 슬라임은 물방울과 퍼지는 웅덩이, 버섯/선인장은 잎과 붉은 조각, 나무 정령은 나뭇잎과 나뭇조각, 해골은 뼛조각, 골렘은 돌조각, 기사와 폭탄은 금속 불꽃과 쇳조각, 게/거미/전갈은 껍질 조각, 불꽃은 불씨, 유령은 푸른 영기 방울이다. 살점 몬스터는 기존 연기만 쓴다.
- 대상 최대 체력의 25% 이상을 한 번에 맞는 치명 타격에는 몸을 가르는 X 자 번쩍임이 더해진다.
- 검증: Snap.exe --matfx out.png <Assets> 가 재질별 타격(위 3칸)과 사망(아래 3칸)을 늘어놓는다.

[나무와 소품 그림자]
- 나무와 소품 그림자도 캐릭터와 같이 존 분위기 색(ShadowStyle.Tone)이고 오른쪽 아래로 길게 드리운다. 나무는 반경의 1.3배, 소품은 폭의 0.18배.

[시간대·날씨에 따른 그림자]
- Core/Logic/LightRules.Shadow(WeatherState)가 그림자 짙기/길이/색조를 정한다. 해질녘: 길이 최대 1.9배, 더 짙고 따뜻한 색. 밤: 절반 이하로 옅고 푸른 색, 길이 0.75배. 비/안개/폭풍: 흐려서 옅고(최대 -55%) 짧다(-45%).
- SceneRenderer 가 장면을 그리기 전에 직전 프레임의 날씨(WeatherLayer.Last)로 ShadowStyle.Light 를 정한다. 캐릭터/나무/소품 그림자가 모두 ShadowStyle.Lit 로 같은 값을 쓴다. 날씨 끔이면 맑은 낮.
- 장면 확인: SNAP_T0=<ms> Snap.exe <GameData> <out> 8 (0 낮, 30000 해질녘, 150000 밤).

[영웅 스킬의 빛]
- App/Render/CastLight.cs: 시전 중에는 직업색 후광이 몸 뒤에서 차오르고(전사 주황/궁수 연두/마법사 보라/창기사 푸른빛), 스킬이 나가는 순간 가슴께에서 220ms 동안 흰 심 섬광이 터지며, 발동 뒤에는 발밑 땅이 직업색으로 밝아졌다 사라진다.
- 땅 조명은 어두울수록(ShadowStyle.Dark: 밤/동굴 0..1) 최대 1.7배 크게 번진다.
- 장면 확인: SNAP_SKILL=1 [SNAP_T0=150000] Snap.exe --heroscene <GameData> out.png
